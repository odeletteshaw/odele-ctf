# Node.js Buffer 内存泄漏：用 Buffer(数字) 读未清零堆内存

**一句话**：旧版 Node 的 `Buffer(n)` 底层走 `malloc` 且**不清零**，返回的缓冲区会残留进程堆里
刚分配过的数据。若 flag 刚被 `eval` 进变量，反复传 `Buffer(大数字)` 就可能把 flag 字符串读出来。

## 触发信号

- Node.js 题目，源码可见 `vm.run` / `vm2` 沙箱执行用户输入，且 flag 被 `eval` 成变量（形如
  `flag_<64位随机串>`）。
- 输入长度有上限（如 ≤12），但可以用表达式（如 `Buffer(800)`）绕过长度限制。

## 套路

- 传 `?data=Buffer(800)`（数字更大命中率更高），服务端把该 Buffer 与别的字符串拼接后回显。
- 一次不一定命中（未清零内存是随机的），**循环请求**直到回显里出现 flag 前缀（如 `hitcon{`）。

## 坑

- 只对**旧版 Node** 有效（Node 8 之后 `Buffer(n)` 改为清零）；现代 Node 要用 `Buffer.allocUnsafe(n)`。
- 数字别超过服务端内存/输出上限。
- 先读源码确认 flag 的变量名 / 前缀，再决定在回显里搜什么。
