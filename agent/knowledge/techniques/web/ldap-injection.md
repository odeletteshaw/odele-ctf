# LDAP 注入：通配符认证绕过与过滤器拼接

**一句话**：登录名/密码被直接拼进 `(&(uid=输入)(password=输入))` 过滤器时，用 `*` 通配符或
`)(`、`|` 之类的结构注入让条件恒真，从而绕过认证（或盲读目录属性）。
关键词：LDAP injection / authentication bypass / filter injection / wildcard。

## 触发信号

- 登录/搜索接口返回「认证失败」或「Welcome」，而参数进入的是目录服务（portal、内网系统、企业登录页）。
- 对 `*`、`)`、`(`、`&`、`|` 的响应不同（报错 / 恒真 / 恒假 / 回显差异）。
- 错误信息里出现 `invalid DN`、`filter`、`ldap_`、`(&(` 等字样。

## 套路

1. **确认参数进过滤器**：密码填 `*` 试恒真；用户名填 `admin`、`*` 对比响应差异。
2. **认证绕过载荷**（按顺序试，先简单后复杂）：
   - 密码 `*`
   - 用户名 `*`
   - 用户名 `admin)(&)`、`admin)(|(password=*))`
   - `*)(uid=*))(|(uid=*`
3. **结构注入**：用 `)(` 提前闭合当前条件，用 `(|(...))` 追加或条件；`&`/`|` 在 URL 里编码成
   `%26`/`%7c`，括号 `%28`/`%29`。
4. **盲注**：若只有真假两种响应，用 `*` 前缀逐字符猜属性值（`admin*`、`adm*`…），先找布尔差异，
   时间盲注（`(|(x=*))`）+ sleep 只在没有布尔信号时用。
5. AD/OpenLDAP 都适用；属性名不确定时轮换 `uid` / `cn` / `sAMAccountName` / `mail`。

## 坑

- `*` 作为密码命中通常是「过滤器变成恒真」，不是密码真的等于 `*`；汇报时按注入说。
- 注入点决定闭合代价：`(&(uid=USER)(password=PASS))` 里，用户名位置要同时闭合两层括号，
  密码位置往往只需 `*`。
- 有些实现会转义 `*()`，先试 URL 编码/双重编码；仍被过滤再考虑属性别名。
- 逐层确认响应差异再推进，别一次塞复杂载荷。
