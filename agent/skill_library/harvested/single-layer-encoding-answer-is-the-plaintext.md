# 单层编码题：穷尽容器隐写排除后「解码结果即答案」，禁止拼音/哈希自造变体

## 触发信号
- 附件只有几百字节，解包后只有一个 txt，单层解码即得一句可读中文/英文短语，但短语本身不像密钥、不像哈希、不含花括号。
- 题目描述只有「注意：得到的 flag 请包上 xxx{} 提交」——这是**格式要求**，不是额外线索。
- 团队里开始出现「要不要转拼音 / 转 hex / 取 md5 / 大小写变体」的讨论，说明已经进入过度变换阶段。

## 步骤
1. **先做穷尽性排除，再决定「提示语即答案」**。对容器逐项排除（每项都要有工具输出）：
   - 条目数/目录条目：`infolist()` 只有 1 目录 + 1 文件；
   - 加密：`flag_bits == 0`；
   - 注释：`z.comment == b''` 且每个 `i.comment == b''`；
   - extra field：只允许标准 `0x7075`（Unicode Path，CRC 校验通过）与 `0x000a`（NTFS 时间戳），其余视为可疑；
   - 压缩流冗余：`zlib.decompressobj(-15)` 解压后 `unused_data == b''` 且 `eof == True`；
   - 字节覆盖：手工遍历 LFH/CDH/EOCD，确认 `0..len(data)` 全部被结构覆盖，无尾部附加数据；
   - 时间戳：NTFS FILETIME 若为荒谬年份（如 2659/1699 年）属工具生成痕迹，不是隐写。
2. 对解码结果做**字符级自证**：`repr()` + `[hex(ord(c)) for c in s]` + `unicodedata.category`，确认无零宽字符、无 BOM、无尾随空格/换行。
3. 上述全部通过后，判定「解码结果本身就是答案」，直接按题目要求包上外层花括号提交，**不再做任何变换**。
4. 若确实需要备选，只列 1 个并明确标注「低可能性、非工具输出」，不要把它当结论上报。

## 证据
- 本次：448 字节 zip 被 LFH@0 / LFH@47 / CDH@184 / CDH@283 / EOCD@426 完全覆盖，comment 空、extra 仅 0x7075+0x000a、deflate `unused_data` 空且 `eof=True`、`flag_bits=0`；解码结果 6 个汉字全为 Unicode 字母类，无隐藏字符 → 判定提示语即答案。
- 反证：把同一字节串按 GBK 解读得到乱码、按 base64/base32/hex 解读全部失败或得二进制垃圾，说明不存在第二层编码。

## 坑
- **「包上 xxx{}」不是转写指令**：它只规定外层格式。把中文原文改成拼音（如把 6 个汉字转成 `nayenihenbangoo`）属于自造答案，且无法用任何工具输出佐证。
- **别把「太简单」当成「还有一层」**：单层编码题在入门 misc 里极常见；继续套 base64/rot13/hex 只会把正确结果破坏成乱码，然后误判为「解错了」。
- **别把备选当结论**：一旦在报告里写出拼音/哈希变体，后续节点会把它当线索继续追，浪费整轮。备选要么不写，要么明确标注「非工具输出、已排除」。
- **上报前必须在本次工具输出里看到完整字符串**：从上一轮摘要里抄答案容易漏字/错字（尤其中文），重新跑一次解码并打印 `repr()` 最稳。
- 交叉验证要「独立重算」而不是「复述」：让另一个节点自己手工遍历容器结构，而不是读前一个节点的结论，才能发现真正的分歧。
