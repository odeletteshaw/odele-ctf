# 干支纪年编码：天干地支→60甲子序数→ASCII，"+甲子"即+60

## 触发信号
- 附件（常为 zip 内单个 txt）正文是一串中文「年份」：每项恰好两字，首字属天干、次字属地支，用逗号/顿号分隔。
- 文中出现提示语 `+甲子`（或 `甲子`、`六十甲子`、`一甲子`），并给出一个「key 值：外层格式{占位符}」的模板行。
- 题目描述只有「得到的结果请包上外层花括号提交」——模板里的占位符是**格式说明**，不是答案。

## 步骤
1. 用正则从正文里抠出所有干支对，避免把提示语里的 `甲子` 也当成密文（它本身是合法干支对，序数 0，会被误抓成一项）：
   ```python
   pairs = re.findall(r'[甲乙丙丁戊己庚辛壬癸][子丑寅卯辰巳午未申酉戌亥]', txt)
   ```
2. 天干 10、地支 12，干支对唯一确定 0..59 的甲子序数 n，用中国剩余定理解：
   ```python
   gan='甲乙丙丁戊己庚辛壬癸'; zhi='子丑寅卯辰巳午未申酉戌亥'
   n = [k for k in range(60) if k%10==gan.index(p[0]) and k%12==zhi.index(p[1])][0]
   ```
   等价闭式：`n = (6*g - 5*z) % 60`（g、z 为 0-based 序）。
3. **`+甲子` = 加 60**（一甲子 = 60 年），即 `chr(n + 60)`。这样 0..59 的序数被抬到 60..119，正好覆盖大写字母与部分小写/符号区。
4. 若结果不是可打印 ASCII，再试 1-based（`n+1+60`）或 `n+64`/`n+96` 等偏移；但**优先选能产出全字母/全可打印的那一组**，不要盲试。

## 证据
- 本次：8 个干支对 → 0-based 序数落在 0..59 区间 → 各 +60 → 得到 8 个字符，全部落在 A–Z，与模板「纯大写串」的形态一致，长度也与模板占位符个数吻合。
- 反证：不加 60 直接 `chr(n)` 得到一串控制字符（不可打印）；`n+64` 得到含方括号的串（非字母）→ 两种偏移均被排除，只剩 `+60`。

## 坑
- **模板占位符不是答案**：正文里那行「key 值：外层格式{占位符}」只说明答案形状，直接照抄提交等于把题面抄回去。必须真正解出花括号内的串。
- **提示语里的 `甲子` 会被正则误抓**：`+甲子` 中的 `甲子` 是合法干支对（序数 0），不过滤会多出一项，导致长度与模板不符、结果错位。用「项数 = 模板内字符数」或「剔除紧跟 `+` 的那一项」来校验。
- **0-based vs 1-based 差 1**：甲子=0 还是甲子=1 两种约定都存在，先按 0-based 算，若结果不可打印再整体 +1，不要逐项乱调。
- **抄前序节点的中间结果会带错字**：干支字形相近（如丙/丁、戌/酉），转录时极易错一项，结果里就会出现一个非字母字符。凡出现非字母字符就是抄错或读错的信号，必须回原始字节重读 `repr(z.read(name))` 重新解析，而不是在错误结果上继续调偏移。
- 干支序数表别手写错：天干序 甲0乙1丙2丁3戊4己5庚6辛7壬8癸9；地支序 子0丑1寅2卯3辰4巳5午6未7申8酉9戌10亥11。
