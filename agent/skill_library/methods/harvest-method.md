# 知识收割规则

**一句话**：只把可复用、此前未覆盖的技术写入技能库；宁缺毋滥。

## 何时收割

- 出现了库里没有的新技术、新绕过、新工具用法，并且能复用到其他题。
- 已有的卡覆盖了同一技术 → **跳过**，不要新增或改写。
- 没有新知识 → 不调用工具，直接说明「本次无需收割」。

## 硬规则（`harvest_skill` 工具也会强制）

1. **一题最多新增 2 张卡**，每张只讲一个技术点。
2. **不写** flag、题目名、目标域名/IP、一次性 payload、过程流水账。
3. 只写通用方法：触发信号 → 步骤 → 证据 → 坑。
4. 标题去重；与现有卡高度重合会被拒绝。
5. 标签必须来自现有技能库标签；系统会自动加 `harvested`。
6. **不要修改已有卡片**；不确定是否重复时，先用 `search_role_skill` 检索。
7. 正文 120–6000 字符；结构清楚，不写废话。

## 卡片结构

```
## 触发信号
## 步骤
## 证据/验证
## 坑
```

## 反例

- 「这道题用 admin'-- 拿到了 flag」→ 含题目与 payload，且已有 SQL 卡覆盖。
- 「先扫目录再打」→ 太泛，不是可执行技术。
- 把整段会话粘贴进正文 → 冗杂，拒绝。
